# Deployment & Infrastructure Configuration

## Local Development
- PHP 8.2+
- Composer
- Database (SQLite / MySQL)
- `php artisan serve` for local server.
- `php artisan queue:work` (optional, for queued tasks).
- Storage uses `local` disk.

## Staging & Production
### Environment Variables
Production `APP_ENV` must be set to `production` and `APP_DEBUG` must be `false`. `APP_KEY` must be a valid base64 key generated by `php artisan key:generate`.
Ensure `APP_URL` matches the deployed domain to properly generate signed URLs for private file downloads.

### Trusted Proxy (HTTPS/Load Balancers)
If deploying behind an AWS ALB or Cloudflare proxy, ensure `TrustProxies` middleware is configured correctly. Set `ASSET_URL` or `FORCE_HTTPS=true` if assets generate with `http://`.

### Private Storage / S3
Configure `FILESYSTEM_DISK=s3` in production. Add AWS credentials in `.env`:
`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_BUCKET`.
**DO NOT make this bucket public.** All attachment downloads must route through the `GET /api/v1/files/{type}/{id}` signed URL endpoint.

### Email Configuration
Provide valid SMTP or SES credentials:
`MAIL_MAILER=smtp` (or ses, postmark)
`MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, `MAIL_FROM_ADDRESS`

### Queue Configuration
Keep `QUEUE_CONNECTION=database` or switch to `redis`.
Start worker daemons using Supervisor:
```ini
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/artisan queue:work database --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
user=www-data
numprocs=2
```

### Scheduler
Not currently required. There are no cron entries in `routes/console.php`.

### Observability
Monitor standard Laravel logs `storage/logs/laravel.log`. The `audit_logs` table automatically records sensitive admin changes.
Check `/api/v1/health` for basic up/down status.

### Rollback
Run `php artisan down` to put the app in maintenance mode. Rollback migrations using `php artisan migrate:rollback` if a bad migration was deployed.
